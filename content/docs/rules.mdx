## DOCS Rules

This page teaches **agents** and **developers** how to correctly add, edit, and classify pages in the OPTX documentation system. Follow these rules to keep the MOA knowledge graph, AGT tensor classification, and navigation consistent.

If you're using **jettoptx-docs as a template** for your own project, this is your walkthrough for understanding the system and customizing it.

---

## For Agents & LLMs

When you add or edit a documentation page, you **must** complete every step below. Skipping any step breaks the knowledge graph or navigation.

### 1. MDX Page Structure

Every doc page is an `.mdx` file in `content/docs/<section>/`. Each file **must** have frontmatter:

```yaml
---
title: Your Page Title
description: One-line summary of what this page covers
icon: Rocket  # Lucide icon name for sidebar
---
```

Frontmatter does not put the page in the sidebar. Add the slug to that section's `meta.json` `pages` array. A file left out of the array can still be routed, but it stays off the sidebar. `next.config.mjs` redirects run first: a redirected path never shows its MDX file.

### 2. AGT Tensor Classification

Every page **must** be classified with a primary AGT (Agentive Gaze Tensor):

| Tensor | Color | Hex | Use For |
|--------|-------|-----|---------|
| <span style={{color: "#eab308"}}>**COG**</span> | Yellow | `#eab308` | Analytical pages: architecture, protocol internals, APIs, reference material |
| <span style={{color: "#f43f5e"}}>**EMO**</span> | Pink | `#f43f5e` | Relational pages: identity, personality, agent interaction, human-facing systems |
| <span style={{color: "#60a5fa"}}>**ENV**</span> | Blue | `#60a5fa` | Spatial pages: infrastructure, networks, addresses, physical topology |

Assign `emo`, `env`, and `cog` scores that **sum to 100**. The highest score determines the primary tensor.

### 3. Add MOA Graph Node

Add a node to `MOA_NODES` in `lib/moa-registry.ts`:

```typescript
{
  id: "your-page-id",
  label: "Short Name",
  group: "section-key",
  agt: "COG",
  radius: 15,
  href: "/docs/section/page",
  description: "One sentence describing this page",
  subLabels: ["Tag 1", "Tag 2", "Tag 3"],
  emo: 20, env: 25, cog: 55
}
```

`PATH_TO_NODE`, `PAGE_AGT`, and mobile `SUB_PAGES` are **derived automatically** from `MOA_NODES`.

### 4. Add MOA Graph Edges (MOC — Map of Context)

Add edges to `MOA_EDGES` in `lib/moa-registry.ts`:

```typescript
{ source: "your-page-id", target: "related-page-id" },
```

Every new page needs **at least 2 edges**: one to its section parent and one cross-section link.

### 5. Mobile Sidebar

`MOBILE_SUB_PAGES` is derived from `MOA_NODES` by group. When adding a **new top-level section**, update `NAV_SECTIONS` in `components/mobile-sidebar.tsx`.

### 6. PATH_TO_NODE

No manual step — `augment-space-btn.tsx` and `mdx-link.tsx` import `PATH_TO_NODE` from `lib/moa-registry.ts`.

### 7. Navigation Ordering

Add every page slug to its section `meta.json` `pages` array. Order in the array is sidebar order. If adding a **new top-level section**, add its folder name to `content/docs/meta.json`:

```json
{
  "pages": ["dojo", "getting-started", "...", "your-section"]
}
```

### Redirects override the page

`redirects()` in `next.config.mjs` wins over the MDX route. Before you publish or restore a page, delete any redirect whose `source` is that path. Leave redirects in place for retired URLs only: Hermes features, `/docs/astrojoe/agent-features` (now the [JOE Agent API](/docs/astrojoe/api)), access-tier URLs, folded architecture pages, and the JettChat mode splits.

### 8. Style & Naming

- **Fonts**: D-DIN Expanded Regular for the `OPTX DOCS` wordmark; IBM Plex Sans for UI, sidebar titles (all caps, 500), and article body; IBM Plex Mono for code snippets and embedded charts only.
- **OPTX Auth lockup**: **It's you** (apostrophe). Never "Its you". Porch pages are the org source of truth — product repos do not ship this tagline.
- **Colors**: `var(--color-orange-500)` for OPTX-orange accents — **never hardcode `rgb(255, 105, 0)`**. The var resolves to neon `#FF6900` in dark mode and burnt brick `rgb(220, 78, 31)` in light mode. AGT tensor colors are still hardcoded by design.
- **Icons**: Use [Lucide](https://lucide.dev) icon names in frontmatter
- **Descriptions**: One sentence per concept, keep it concise

### 9. Changelog Currency (NON-NEGOTIABLE)

**Every shipped change MUST update the changelog in the same session.** Applies to LLMs, VLMs, and human contributors equally.

The changelog is [`content/docs/reference/changelog.mdx`](/docs/reference/changelog), with `### Added`, `### Changed`, `### Fixed`, `### Security`, and `### Process` subsections as needed. When the public version changes, bump the **Current Version** line in `README.md` in the same change.

The site footer is house chrome. It does not contain a changelog or a "Last updated" line. Do not add one back to `components/footer.tsx`.

Land the changelog update in the **same commit** as the work, or as an **immediate follow-up commit** before the session ends.

**Versioning:**
- Within the same calendar day, **extend the most recent version entry** with new bullets.
- **Bump** (e.g. `v2.2.4` → `v2.2.5`) when crossing into a new day OR shipping a clearly distinct release.

## For Human Developers

### Adding a Page

1. **Create** an `.mdx` file in `content/docs/<section>/`
2. **Add frontmatter**: `title`, `description`, `icon`
3. **Write** your content in Markdown (JSX components supported)

### Classify Your Page

Pick the dominant cognitive dimension:
- **COG** — Technical, analytical, requires reasoning
- **EMO** — About identity, social interaction, agent personality
- **ENV** — Infrastructure, networks, spatial topology

### Register the Page

| File | What to Add |
|------|-------------|
| Section `meta.json` | Page slug in `pages` (this puts it in the sidebar) |
| `lib/moa-registry.ts` | `MOA_NODES` entry + at least two `MOA_EDGES` |
| `content/docs/meta.json` | Folder name, only for a new top-level section |
| `next.config.mjs` | Remove any redirect whose `source` is this path |

`PATH_TO_NODE`, `PAGE_AGT`, and mobile `SUB_PAGES` are derived from `MOA_NODES`. Do not edit `components/moa-visual.tsx`, `components/augment-space-btn.tsx`, or a hand-maintained path map. A page that should open directly needs its own `href`. `PATH_TO_NODE` keeps the last node when several share a URL. The folded architecture nodes all use `/docs/reference/architecture` on purpose — that URL opens the appendix.

### Always Update the Changelog (Same Session)

Update `content/docs/reference/changelog.mdx` in the same commit or an immediate follow-up. Bump **Current Version** in `README.md` when the version changes. The footer has no changelog block.

### Using jettoptx-docs as a Template

jettoptx-docs is designed to be forked and customized:

1. **Fork** — `git clone https://github.com/jettoptx/jettoptx-docs.git my-docs`
2. **Replace** — Swap MDX files in `content/docs/` with your own
3. **Customize graph** — Edit `MOA_NODES` and `MOA_EDGES` in `lib/moa-registry.ts`
4. **Update nav** — Modify `content/docs/meta.json` and `lib/source.ts`
5. **Deploy** — Push to GitHub, connect to Vercel, done

## Checklist

When adding a new page, use this checklist:

- [ ] Created `.mdx` file with frontmatter (title, description, icon)
- [ ] Chose primary AGT tensor (COG/EMO/ENV)
- [ ] Added node to `MOA_NODES` in `lib/moa-registry.ts`
- [ ] Added edges to `MOA_EDGES` in `lib/moa-registry.ts` (min 2)
- [ ] Listed the slug in the section `meta.json` `pages` array
- [ ] (If new section) Updated `content/docs/meta.json` and `NAV_SECTIONS` in `mobile-sidebar.tsx`
- [ ] Removed any `next.config.mjs` redirect for this path
- [ ] Updated `content/docs/reference/changelog.mdx` and, if the version changed, the README **Current Version** line
